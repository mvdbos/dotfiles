# AGENTS.md

Personal dotfiles managed with GNU Stow. Each top-level directory (`shell/`, `bash/`, `zsh/`, `vim/`, `git/`, `ssh/`, `wget/`, `certs/`, `opencode/`, `phoenix/`, `ideavim/`) is a stow package.

## Hard constraints

- Repo must live at `~/.dotfiles`: `shell/.profile`, aliases, and `validate_setup.sh` source `$HOME/.dotfiles/platform_detector.bash`, and stow symlinks point into `~/.config/dir_aliases`.
- Never hand-edit files in `$HOME`; edit the package file and `stow -R <pkg>` from the repo root. `stow_dotfiles.sh` is the source of truth for which packages are installed.
- `shell` must be stowed with `--no-folding` (see `stow_dotfiles.sh`); folding breaks user symlinks under `~/.config/dir_aliases`.
- Vim plugins are git submodules; run `git submodule update --init` after a fresh clone.

## Validation (mandatory for shell changes)

Run `./validate_setup.sh` after editing `bash/.bashrc`, `zsh/.zshrc`, `shell/.profile`, `shell/.config/shell/*`, `setup.sh`, or `stow_dotfiles.sh`. It copies the repo into a throwaway `HOME`, stows shell/bash/zsh, and asserts 11+ checks; CI (`copilot-setup-steps.yml`) runs the same script on Ubuntu and blocks PRs on failure. Zsh alias checks are informational outside interactive shells.

## Shell config conventions

- `shell/` is shared by bash and zsh: keep it POSIX (no `[[`, no `seq`, no bashisms). Use `builtin cd` in functions because `cd` is aliased to `cdbm`.
- `bash/.bashrc` and `zsh/.zshrc` both source `~/.config/shell/{aliases,functions}` and set `alias cd='cdbm'`.
- Circular-source guard: `.bashrc` exports `BASHRC_SOURCED=1` before sourcing `.profile`; `.profile` only sources `.bashrc` when the guard is unset. Don't remove either half.
- Platform detection: source `platform_detector.bash`; on Darwin, aliases map to Homebrew GNU coreutils (`gls`, `grm`, `gmv`, ...). Linux falls back to native tools.
- `zsh/.zshenv` hardcodes `/opt/homebrew` and macOS-only setup; zsh also expects oh-my-zsh at `$HOME/.oh-my-zsh` (not vendored here).

## OpenCode plugins and config

- `opencode/.config/opencode/plugins/*.ts` are auto-loaded globally by OpenCode **as server plugins**. TUI plugins (`default export { id, tui }`) live in `opencode/.config/opencode/tui-plugins/` and are only loaded when listed in `opencode/.config/opencode/tui.json` under `plugin`; keeping them out of `plugins/` prevents the server loader from importing (and failing on) TUI-only modules. Never put supporting modules in `plugins/` — every `.ts` directly there is loaded by the server loader. Support code lives in sibling dirs (`explore-controls/`, `subagent-controls/`, `todo-reconcile/`, `async-reasoning-titles/`).
- `plugins/subagent-concurrency.ts` enforces independent global SQLite locks for configured subagent types (`explore` and `general`, one each). Policy, queueing, lifecycle handling, and timeout overrides live in `subagent-controls/`; see its README before changing admission behavior. `general` intentionally has no model override and inherits the invoking main model. Keep experimental background subagents disabled and only one main-model session active; subagent locks do not serialize unrelated primary requests.
- `tui-plugins/async-reasoning-titles.ts` (TUI) and `plugins/async-reasoning-titles-strip.ts` (server) are the two halves of one feature. The TUI plugin generates collapsed reasoning titles using only the plugin `model` option (`tui.json` pins `omlx/Qwen3.5-0.8B-8bit`); with no model option the feature stays disabled — there is no `small_model` fallback. It embeds them as a `**Title**\n\n` prefix so the existing TUI header parser renders them, and records the exact title in part metadata (`metadata["async-reasoning-titles"]`). It skips signed reasoning (`metadata.anthropic.signature`) because rewriting that text breaks provider replay; per-block manual expansion is not visible to TUI plugins, so eligibility uses thinking mode, an untitled unsigned block with usable text, and either completion or a full capped prefix. Input is the first `maxInputChars` chars (default 4,000), and generation starts once a streaming block passes the `minChars` floor (default 200, `tui.json` pins 400), so blocks longer than the floor are titled while still streaming; the result is held until the block completes, then applied only if it is still unsigned, untitled, and starts with the summarized prefix. The server plugin strips marker-verified prefixes from outgoing requests in `experimental.chat.messages.transform` (request-scoped; DB keeps titles) so provider context and prefix caches never see titles. Strip only removes a prefix when metadata records the same title, so model-authored bold lead-ins are untouched; both plugins share `async-reasoning-titles/helpers.ts`.
- `plugins/todo-reconcile.ts` is only a re-export of `todo-reconcile/src/plugin.ts`; edit `src/`, then fully restart OpenCode. Do not also install the built `todo-reconcile/dist/` bundle — it would load twice.
- `tui-plugins/ds4-stats.tsx` renders the active session's averages into the `sidebar_content` slot (`{label} · session avg` header, then `pp <n> · tg <n> tok/s` and `cache <n>% · model <26m|1h 26m> · total <26m|1h 26m>`; pp is 0-decimal, tg/cache 1-decimal, numbers right-aligned in fixed widths; pp/tg are deliberately uncolored — only cache hit carries good/warn/bad), but only when that session actually talks to the local ds4 server: the latest message's model ref must name a provider whose `baseURL` matches `DS4_HOST`/`DS4_PORT` (default `127.0.0.1:8000`), or a pinned `provider`/`providers` option. Averages span the whole OpenCode session (from session creation, not plugin start): the parser seeds from the full log at startup, and message history comes from `api.client.session.messages` with `limit`/`before` cursor pagination — the TUI store itself only keeps the last 100 messages per session, which silently truncated every stat before this; fetched histories are cached per session and kept fresh by upserting `message.updated` info and finalized tool spans from `message.part.updated` (dropping `message.removed`/`message.part.removed`; spans dedupe by part ID and keep the larger end between fetch and events), so only assistant usage from those ds4 providers is counted and sessions that switched models do not mix. It tails the ds4 server log (ds4-monitor grammar; variant auto-detected from pid files exactly like `~/.bin/ds4-monitor`, or pinned with the `variant`/`log` options) and attributes each logged request to an assistant message by prompt total (`input + cache.read + cache.write`), claiming each request once. Prefill/decode averages are token-weighted (Σprefetched/Σsecs, Σgen/Σsecs) over matched turns; cache hit % comes from message tokens only, so it stays per-session-exact even when no request matched (and when old log lines are gone); `model` sums prefill+decode seconds of matched requests (ds4 server busy time), and `total` adds the union of finalized tool spans (completed or errored, including aborted) from that provider's assistant messages, so parallel calls are not double counted while user idle, queue waits and unmatched requests stay out; both render as minutes or hours+minutes and hide below one minute, and since total is always at least model, a sub-minute model with minute-plus tools shows `total` alone. Scope is session averages, not live ticks. Parsing/correlation/formatting live in `ds4-stats/helpers.ts`; the plugin polls on `pollMs` (default 1000) and recomputes on `message.updated`. The `Stats` component deliberately avoids reactive JSX: OpenCode 1.18.31 does not run the Solid transformer over external file plugins (verified with a probe — dynamic JSX evaluates once and never re-renders, while renderable refs repaint fine), so it renders static structure and a `createEffect` on the plugin's version signal writes `content`/`fg`/`visible` into refs imperatively; keep new slot UI on that pattern. Bare `solid-js` imports in plugins resolve to the client build in the TUI process (OpenTUI runtime rewrite) but to the SSR build under plain `bun test`, so the component test must run with `--preload @opentui/solid/preload`.
- Plugins rely on experimental OpenCode hooks verified against OpenCode 1.18.31; after plugin changes, start a fresh OpenCode process.

  - async-reasoning-titles, from `opencode/.config/opencode/`: `bun test ./async-reasoning-titles/helpers.test.ts ./async-reasoning-titles/plugin.test.ts ./async-reasoning-titles/strip-plugin.test.ts` (hermetic), `bun test ./async-reasoning-titles/integration/titles.integration.test.ts` (real OpenCode binary, mock OpenAI-compatible LLM, TUI attach under a `script` PTY).   - image-display-annotation, from `opencode/.config/opencode/`: `bun test ./image-display-annotation/helpers.test.ts ./image-display-annotation/plugin.test.ts` (hermetic). `plugins/image-display-annotation.ts` appends a zero-width-space-marked `Displayed image: <abs path>` line to the assistant text part that completes after a successful `image_display` (server hook `experimental.text.complete`, before the part is stored), so the path shows in the TUI transcript even with tool details hidden. The zero-width-space marker trails the annotation line; a leading marker makes OpenTUI's streaming markdown renderer (0.4.5, pinned by OpenCode 1.18) drop a visible character at the line end or wrap seam, so do not move it. The same plugin strips marker-verified annotations in `experimental.chat.messages.transform`, so outgoing provider requests and prefix caches stay clean (same pattern as `async-reasoning-titles-strip.ts`). Pending paths are cleared by `chat.message` so an interrupted turn cannot leak into a later one. This plugin is deliberately TUI-independent; the TUI plugin only spawns viewers.
  - ds4-stats, from `opencode/.config/opencode/`: `bun test ./ds4-stats/helpers.test.ts ./ds4-stats/plugin.test.ts` (hermetic; fixtures are real ds4 server log lines), `bun test --preload @opentui/solid/preload ./ds4-stats/component.test.tsx` (hermetic component render; proves ref-based updates and ds4 gating; the preload is required because plain `bun test` resolves bare `solid-js` to the SSR build).
- Canonical runtime deps for the global config are `opencode/.config/opencode/package.json` (installed by `setup.sh`); `todo-reconcile` pins its own SDK version. Root `package.json`/`node_modules` pins a different, unrelated `@opencode-ai/plugin` (1.1.48) — don't assume version bumps there affect plugins.
- `plugins/rtk.ts` only delegates to the `rtk` binary; rewrite rules live in rtk's Rust registry, not this repo.
